# Первые 90 дней — подготовка иностранного студента к обязательным процедурам

Бот показывает план, чек-лист документов и напоминания. Целевой пилот: совершеннолетний
иностранный первокурсник, первый въезд с 01.09.2026 для учёбы более чем на 90 дней,
общежитие КФУ, без РВП/РВПО/ВНЖ и ранее пройденных процедур. КФУ — кандидат, не партнёр.

**Статус:** бот работает в MAX в демо-режиме (APP_MODE=demo, все сообщения помечены ДЕМО).
Выкаченный коммит — поле `commit` в https://81-26-178-75.sslip.io/health (с 30.09 —
`cd5ec9e`, docs/verification-2026-09-30.md). Шаги 1–24 docs/max-manual-check.md пройдены
руками 25–27.09 на прежней версии: мобильная — со скриншотами в images/max-check, веб — со
слов проверявшего (docs/verification-2026-09-27.md); прогон `cd5ec9e` в MAX ещё не записан.
Все нормативные правила — draft; APP_MODE=live их блокирует.

**Проверка за 5 минут (в MAX, мобильная или веб-версия):**

1. Открыть [max.ru/t149_hakaton_max_bot](https://max.ru/t149_hakaton_max_bot) → «Начать» или `/start`.
   Язык может выбраться сам по языку клиента.
2. Язык → «Продолжить» → «Да, совпадает» → «Казахстан».
3. Дата въезда — **сегодня минус 22 дня** (30.09 → `08.09.2026`, 05.10 → `13.09.2026`).
   Бот пускает даты с 01.09.2026 по сегодня. С фиксированной `01.09.2026` медосвидетельствование
   с 01.10 уже просрочено, и напоминание «за 7 дней» не увидеть.
4. Ожидается план: медосвидетельствование через 7 дней («скоро»), дактилоскопия — через 67.
5. «🔔 Включить напоминания» → после 09:00 МСК сразу приходит «Напоминание: Медицинское
   освидетельствование — …» (раньше 09:00 — в 09:00). «Подробнее» открывает карточку.
6. В карточке — отметки документов, «Открыть норму», «Не получилось» → «Скопировать вопрос»;
   под планом — «📅 Добавить сроки в календарь» (файл `.ics`).
7. Мини-приложение — кнопка MAX слева от поля ввода: тот же план, отметки видны и в чате.
Развёртывание — [docs/deploy.md](docs/deploy.md), архитектура — [docs/architecture.md](docs/architecture.md).

## Запуск одной командой

```sh
docker compose up --build -d
```

Нужны Docker Engine, Compose v2, сеть для Docker Hub и npm при сборке. На хосте порт
3000 привязан к 127.0.0.1; внутри контейнера также 3000. Другой порт:
`BOT_PORT=3300 docker compose up --build -d`.

```sh
curl http://127.0.0.1:3000/health
docker compose logs --tail=30 bot
docker compose run --rm bot node dist/demo.js --script
```

Последняя команда проходит синтетический сценарий во временной схеме PostgreSQL
(удаляется после прогона),
с явно обозначенной учебной датой 24.09.2026; проверяет одно напоминание, отметку
о прохождении и остановку уведомлений. Профили сервера она не меняет.

Без Docker: Node.js 24+, `npm ci --ignore-scripts`, `npm run build`,
`npm run demo` — интерактивный терминал, `npm run demo:check` — сценарий,
`npm start` — HTTP-сервер (нужен PostgreSQL 16+ и `DATABASE_URL`). Демо и тесты
поднимают временный PostgreSQL сами (dev-зависимость `embedded-postgres`), Docker
для них не нужен; учебный профиль терминала удаляется при /exit.

Для тех, кто коммитит (люди, Codex): `git config core.hooksPath .githooks` включает
хуки pre-commit (секреты в индексе, задача) и pre-push (задача); см. GIT.md, «Git-хуки».

## Основной сценарий и проверка

1. /start → русский или English → условия хранения данных.
2. Подтвердить границы пилота. «Нет / не знаю» выводит контакт КФУ без расчёта.
3. Выбрать гражданство (страны названы на языке пользователя) и ввести дату въезда —
   `01.09.2026` или `2026-09-01`, в пределах с 01.09.2026 по сегодня. Неверную дату можно
   исправить. Даты в ответах пишутся словами: «30 сентября 2026 г.». Чтобы увидеть
   напоминание сегодня, ввести дату «сегодня минус 22 дня» (см. «Проверка за 5 минут»).
4. Получить план двух процедур: медосвидетельствование и дактилоскопия.
   Миграционный учёт оформляется отдельно через университет.
5. Открыть карточку, отметить документы; посмотреть источник и дату сверки;
   кнопка «Открыть норму» ведёт на текст закона.
6. Включить напоминания — пока они выключены, кнопка «🔔 Включить напоминания» стоит первой
   под планом. Напоминания приходят за 7, 3 и 1 день, в 09:00 по Москве, и один раз на следующий
   день после расчётной даты, если процедура не отмечена: «срок был до…, пройти всё равно нужно»
   со ссылкой на карточку просрочки (D-021). Если включить
   позднее 09:00 в соответствующий день, сообщение уйдёт при обработке очереди.
   «Подробнее» в напоминании открывает карточку, даже если после него были другие действия.
   «📅 Добавить сроки в календарь» присылает файл first-90-days.ics: события на даты
   сроков с напоминаниями календаря в те же дни и час — работают и при выключенных
   уведомлениях бота. Повторная выгрузка обновляет события, а не дублирует.
7. «Процедура пройдена» → фактическая дата. Для повтора отдельно показываются
   рекомендуемая дата и окончание расчётного окна.
8. «🗓 Запланировать визит» в карточке: день похода в ПВС или клинику (с сегодня и до года вперёд). Накануне
   в 18:00 по Москве бот присылает, каких документов из чек-листа ещё не хватает; визит попадает и в
   файл `.ics` с напоминанием календаря накануне (D-039). Работает при включённых напоминаниях.
9. Продление регистрации и визы (правила вуза, D-040): в карточке «📅 Указать дату окончания визы /
   регистрации» — бот считает дату по правилу вуза («не позднее чем за 45 дней», у КФУ для визы ещё
   «не ранее чем за 90»), показывает её в плане и в `.ics` и напоминает за 7, 3 и 1 день. Это расчёт от
   введённой студентом даты, а не решение МВД; «за 1,5 месяца» у ИТМО остаётся текстом.
10. «🗺 Как добраться» — ссылка на поиск адреса в Яндекс Картах: у процедур вуза — офис вуза, у федеральных
   процедур — место, куда направляет сам вуз, со ссылкой на его страницу (КФУ: медосвидетельствование в
   МСЧ КФУ; ИТМО и СПбГЭУ: ФГУП «ПВС», ул. Красного Текстильщика). Геолокация не запрашивается (D-041).
11. «Не получилось» в карточке собирает готовый вопрос КФУ с названием процедуры,
   расчётным сроком, гражданством и датой въезда; кнопка «Скопировать вопрос» кладёт
   его в буфер, «Открыть страницу КФУ» — ведёт на контакты. Отправляет пользователь сам.
   /stop выключает напоминания; /delete запрашивает подтверждение удаления.
12. /change или кнопка «Изменились обстоятельства» под планом (D-061): переезд, возвращение из
   поездки или больницы, гостиница или больница, новый паспорт. Бот спрашивает дату события и
   считает срок уведомления о прибытии в рабочих днях (109-ФЗ ст. 20 ч. 3 — 7 дней, ч. 3.1 — 1 день;
   календарь D-060) и срок вуза, если его страница называет свой срок (КФУ — следующий рабочий
   день). Показывает обе даты с основаниями и более раннюю как «ваш срок», что передать и куда,
   просит проверить отрывную часть уведомления; напоминает за 3 дня, за день и в день срока, срок
   попадает в `.ics`. Новый паспорт — без срока: «сообщите в вуз» и контакт (ПП № 9 п. 42).
   Нормы — draft (src/data/rules/ru-change.json): при APP_MODE=live /change выключен.

Процедуры вуза без расчётного срока (D-034) — в его профиле, поле `procedures`: у КФУ это
миграционный учёт в общежитии «в течение следующего рабочего дня после заселения» — от даты
заселения, которую бот не знает. План показывает их отдельным блоком «Срок пока не посчитан»:
что сделать, срок словами источника, документы с отметками, ссылка и дата сверки; без
напоминаний и `.ics`. В демо на шаге даты въезда есть кнопка «Показать на примере».

Вуз выбирается ссылкой: max.ru/t149_hakaton_max_bot?start=itmo открывает профиль ИТМО, `?start=spbgeu` —
СПбГЭУ (оба по официальным страницам вузов, сверено 29.09.2026, не партнёры, D-036), без параметра — КФУ. Вручную то же: `/start itmo` до ввода даты или кнопка
«🏫 Я из другого вуза» на вопросе о границах сценария — список вузов каталога и «Моего вуза нет
в списке» (D-035); в мини-приложении — тот же выбор на экране сценария. Как подключить вуз и
проверить профиль (`npm run university:check`) — [docs/add-university.md](docs/add-university.md). Профиль
вуза — файл в src/data/universities: название, страница контактов, кнопки гражданств;
новый вуз добавляется файлом без правок кода. Тексты интерфейса — файлы
src/data/i18n/<язык>.json (сейчас русский, английский, татарский, узбекский и китайский; tt, uz и zh —
машинный перевод, D-024, D-050); новый язык — файл плюс переводы названий в
нормах и профилях вузов, кнопка языка появляется сама (D-020). При запуске бот сверяет
ключи, подстановки и формы множественного числа и не стартует, если перевода не хватает.
Если клиент MAX сообщил язык, для которого есть файл, вопрос о языке пропускается,
переключиться можно кнопкой. В плане, карточке и напоминании
показано «осталось N дней»; после расчётной даты карточка говорит, что срок прошёл,
и готовит вопрос вузу — без оценки последствий.

## QR-плакат вуза: вход в бот одним сканированием

Вуз печатает плакат, вешает его в общежитии, у деканата или раздаёт в пакете
первокурсника. Студент наводит камеру телефона на код — открывается бот в MAX, сразу в
сценарии **своего** вуза: название, страница контактов и готовый вопрос уже его вуза,
ничего выбирать не нужно. Каналом внедрения управляет сам вуз, без рассылок и
интеграций: чтобы подключить новый вуз, достаточно файла профиля и напечатанного листа.

```sh
npm run build
npm run qr               # плакаты для всех профилей: posters/kfu.svg, posters/itmo.svg
npm run qr -- itmo       # только для одного вуза
```

Что внутри:

- QR-код ведёт на диплинк `https://max.ru/t149_hakaton_max_bot?start=<вуз>`; MAX передаёт
  `start` боту в событии `bot_started`, и бот выбирает профиль до построения плана (D-018).
- Лист A4 в векторе (SVG): печатается без потери чёткости в любом размере; открыть в
  браузере и «Печать → PDF» или `rsvg-convert -f pdf posters/kfu.svg -o kfu.pdf`.
- Тексты берутся из `src/data/i18n`. Языки плаката задаёт поле `posterLanguages` в
  профиле вуза (КФУ: русский, татарский, английский, китайский); без поля — все языки
  интерфейса. Код с коррекцией ошибок уровня Q читается и с помятого или бликующего
  листа; при большом числе языков код уменьшается, но не меньше 6 см — иначе генератор
  откажется печатать (на A4 помещается около четырёх языков, D-050).
- В демо-режиме на листе надпись «ДЕМО · учебные данные»; ИТМО и СПбГЭУ —
  не партнёры.
- Проверено: оба плаката распознаются `zbarimg` в точный диплинк; тест
  `tests/poster.test.ts` делает то же, если в системе есть `rsvg-convert` и `zbarimg`,
  и проверяет, что ссылка с плаката открывает сценарий нужного вуза.

Переменные: `BOT_LINK` (по умолчанию `https://max.ru/t149_hakaton_max_bot`),
`POSTERS_DIR` (по умолчанию `./posters`, в git не попадает). Генератор работает
локально и базы данных не требует; библиотека QR — `qrcode-generator` (MIT, без
зависимостей), только для разработки.

Синтетический KZ, въезд 01.09.2026: даты 30.09.2026 и 29.11.2026 (день въезда входит в
срок — D-016, D-044).
Медпроцедура 20.09.2026: рекомендуемая дата 20.09.2027, конец окна 20.10.2027.
Это примеры формул справочника, утверждённого командой без юриста (D-044), не юридические рекомендации.
BY и въезд до сентября не получают нормативного плана.

Для локального демо .env не нужен. .env.example содержит демонстрационные значения.
Секреты помещаются только в исключённый из Git файл .env.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| APP_MODE | demo | demo или live; live требует approved-правил |
| TRANSPORT | console | console или max |
| MAX_BOT_TOKEN | пусто | для max |
| WEBHOOK_SECRET | публичное локальное демозначение | для max нужен собственный секрет 32–256 букв, цифр, _ и - |
| BOT_PORT | 3000 | порт Compose на хосте |
| PORT / HOST | 3000 / 127.0.0.1 | прямой запуск; Docker задаёт HOST=0.0.0.0 |
| POSTGRES_PASSWORD | публичное локальное демозначение | пароль PostgreSQL в Compose, только буквы и цифры; для max нужен собственный |
| DATABASE_URL | — (обязательна) | строка подключения PostgreSQL; Compose собирает её сам из POSTGRES_PASSWORD |
| DEPLOYED_COMMIT | пусто | хеш выкаченного коммита (7–40 hex) для поля `commit` в `/health`; пустое или некорректное значение — поля нет |
| RULES_PATH | ./src/data/rules/ru-student.json | путь к справочнику |

| DEFAULT_UNIVERSITY | kfu | профиль для входа без диплинка |
| TEXTS_PATH | ./src/data/i18n | каталог текстов интерфейса, файл на язык |
| CHANGES_PATH | ./src/data/rules/ru-change.json | нормы «Изменились обстоятельства» (/change) |
| CALENDAR_PATH | ./src/data/calendar/ru.json | производственный календарь для сроков в рабочих днях |
| WEBAPP_BOT | пусто | имя бота для кнопки `open_app` под планом; пусто — кнопки нет |
| WEBAPP_DIR | ./web/dist | каталог собранного мини-приложения, которое отдаёт сервер |
| WEBAPP_DEV_ORIGIN | пусто | origin Vite для локального демо; при `TRANSPORT=max` запрещён |
| RATE_LIMIT_PER_MINUTE | 30 | действий одного пользователя за фиксированное окно 60 с, которое открывает первое действие: сообщения и кнопки чата вместе с запросами мини-приложения по данным запуска (`/api/state`, `/api/action`, `/api/calendar-ticket`, `/api/calendar.ics`); сверх лимита чат не применяет обновление и раз за окно предупреждает, API отвечает 429 |

## Реальная интеграция MAX

Нужны бот с токеном, HTTPS на 443 с доверенным сертификатом и reverse proxy на
локальный порт. Эти внешние условия Docker не заменяет.

1. Согласовать владельца токена: один активный потребитель.
2. Установить в .env TRANSPORT=max, токен, собственный WEBHOOK_SECRET и WEBHOOK_URL.
   APP_MODE=demo подходит только для явно обозначенного учебного показа.
3. Запустить сервис, настроить HTTPS и проверить /health извне.
4. После запуска вручную создать подписку MAX: в Docker —
   `docker compose run --rm --no-deps bot node dist/subscribe.js`, без Docker —
   `npm run subscribe`. Скрипт отказывается заменять существующие подписки.
   Подсказки команд после «/» (`/start`, `/plan`, `/change`, `/help`, `/stop`, `/delete`, описания
   ru/en из src/data/i18n): `docker compose run --rm --no-deps bot node dist/commands.js`
   или `npm run commands` (`PATCH /me/commands`, подписку не трогает; `--dry-run` только
   показывает список, D-025).
5. Пройти путь в мобильном и веб-MAX и записать коммит, дату, результат.

Используется официальный @maxhub/max-bot-api 0.3.1, домен platform-api2.max.ru,
Authorization header. Сертификат platform-api2.max.ru выпущен Russian Trusted Root CA
(Минцифры), которого нет в хранилище Node: без него бот принимает webhook, но не может
ответить (UNABLE_TO_GET_ISSUER_CERT_LOCALLY). Корневой сертификат лежит в
certs/russian_trusted_root_ca.pem (SHA-256 D2:6D:…:CF:31, проверяется тестом), Docker-образ
подключает его через NODE_EXTRA_CA_CERTS. Без Docker переменную задают в окружении
процесса: `NODE_EXTRA_CA_CERTS=certs/russian_trusted_root_ca.pem npm start` — из .env
(--env-file) Node её не читает. TLS-проверку не отключать.
[Документация API](https://dev.max.ru/docs/chatbots/bots-coding/prepare),
[требования webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions).

## Мини-приложение

Мини-приложение MAX живёт рядом с ботом в том же процессе и на том же HTTPS-origin:
по условиям платформы оно не бывает отдельным сервисом, а отдавать один контейнер
проще, чем два. Зачем оно нужно помимо чата: план целиком со статусами и чек-лист
документов видны сразу, без прокрутки диалога (`docs/product/mvp.md`, шаг 7).

Сборка и запуск:

```sh
npm run web:install     # npm ci в web/, свой lock-файл
npm run web:build       # tsc --noEmit && vite build -> web/dist
npm start               # сервер отдаёт web/dist и /api/*
```

В Docker бандл собирается отдельной стадией, `WEBAPP_DIR=/app/web/dist`.

Локальная отладка без MAX: собрать бандл (`npm run web:build`), запустить сервер с
`APP_MODE=demo TRANSPORT=console` и открыть `http://localhost:3000/?demo=42`, где `42` —
условный MAX ID (другое число — новый пользователь). Для горячей перезагрузки
`npm run web:dev` поднимает Vite на 5173 и проксирует `/api` на сервер (`http://127.0.0.1:3000`),
сервер тогда запускается с `WEBAPP_DEV_ORIGIN=http://localhost:5173`; открывать
`http://localhost:5173/?demo=42`. Такой запуск работает
**только** при `APP_MODE=demo` и `TRANSPORT=console`: сервер пишет в лог
`[MOCKED: mini app launch data ...]`, а приложение показывает баннер «Запуск без
подписи MAX». В любом другом режиме конфигурация с `WEBAPP_DEV_ORIGIN` не стартует,
а незаверенный запуск получает 401.

Подключение в MAX: в настройках бота указывается публичный HTTPS-URL приложения
(`https://81-26-178-75.sslip.io/` — Caddy отдаёт на бота весь origin) и вариант кнопки
запуска; открывается кнопкой в чате, диплинком `https://max.ru/<бот>?startapp=<вуз>` —
payload выбирает профиль вуза так же, как `?start=<вуз>` у бота, — и кнопкой
«📱 План в мини-приложении» под планом в чате (`open_app` с тем же payload). Эта кнопка
включается переменной `WEBAPP_BOT=<имя бота>` только после регистрации URL: без неё
кнопка открывала бы пустоту. 27.09 приложение открыто из MAX на Android без плашки
«Запуск без подписи MAX» — подпись стартовых данных на настоящем запуске проходит
(docs/verification-2026-09-27.md, шаги 22–24).

Карточка процедуры повторяет ветку чата «Не получилось» / «Срок прошёл — что делать»:
сервер отдаёт тот же готовый вопрос вузу, что чат кладёт в кнопку `clipboard`
(`AppResult.copy`), приложение показывает его с кнопкой копирования и ссылкой на страницу вуза.

Безопасность и совместимость:

- Каждый запрос несёт стартовые данные MAX, сервер проверяет подпись HMAC-SHA256 по
  [официальной инструкции](https://dev.max.ru/docs/webapps/validation) и срок
  `auth_date` (1 час). `initDataUnsafe` и любой MAX ID из тела запроса не
  используются: пользователь берётся только из подписанных данных.
- Бот и приложение работают с одной сессией и одним движком сроков
  (`src/bot/dialog.ts`). Приложение отправляет тот же словарь действий, что и кнопки
  чата, и передаёт номер ревизии: если состояние успели изменить из чата или второго
  окна, приходит 409 и экран перезагружается. Действие выполняется в той же
  транзакции PostgreSQL под блокировкой пользователя, что и webhook, поэтому
  одновременное сообщение в чат не может вклиниться.
- Методы MAX Bridge, которых нет в веб-клиенте (`DeviceStorage`, `SecureStorage`,
  `shareContent`, `downloadFile`, хаптика, биометрия), вызываются только при наличии;
  основной сценарий проходится и в вебе. Файл `.ics` внутри MAX скачивается
  `downloadFile`, в браузере — обычной ссылкой.
- Ссылка на скачивание не может нести заголовок авторизации, а стартовые данные в URL
  попали бы в логи и историю, поэтому `POST /api/calendar-ticket` выдаёт билет на 5 минут,
  подписанный случайным ключом процесса (не секретом webhook, который знает и MAX).

Облик — русский конструктивизм (`D-029`, шрифты — `D-030`): кармин, бумага, чёрный;
Tektur — плакатные заголовки и узкий капс (ось ширины), PT Sans — текст (OFL, в бандле,
без запросов к Google Fonts, лицензия — `web/FONTS-OFL.txt`), фото своего
вуза на старте и в финале (Public Domain / CC0, `web/src/photos/SOURCES.md`). Цвета —
CSS-переменные в `web/src/app.css`, светлая и тёмная тема по настройке системы. Кнопки,
строки, плитки, переключатель и чекбоксы — нативные элементы с ARIA (`web/src/ui.tsx`);
от MAX UI остался корневой `MaxUI`. Дата вводится как ДД.ММ.ГГГГ.

Состав: `web/src/bridge.ts` — обёртка над `window.WebApp`; `web/src/api.ts` и
`web/src/useApp.ts` — клиент и единый стейт с состояниями загрузки, результата и
ошибки; `web/src/screens/` — экраны. Своего словаря у приложения нет: все тексты
приходят в состоянии, сервер берёт их из `src/data/i18n/<язык>.json` (`D-020`), а
строки с числом (обратный отсчёт по процедуре) он отрисовывает сам — формы
множественного числа живут там же. Третий язык — файл в `src/data/i18n`, и всё.
Типы провода — `src/webapp/contract.ts`, по нему же проверяется бандл.

## Состав и архитектура

HTTP webhook → транзакция PostgreSQL под блокировкой пользователя (профиль + отпечаток
события + ответ в очереди; 200 только после COMMIT, при сбое БД — 503) → фоновая
отправка с арендой задания. src/core считает даты, src/data валидирует правила,
src/bot содержит диалог, транспорт и HTTP, src/db — схему, хранилище и импорт из
прежней SQLite, src/webapp — проверку стартовых данных MAX, общий с ботом стейт и
HTTP-слой мини-приложения, web/ — сам бандл на React со своим lock-файлом,
src/main.ts запускает сервис (`D-022`, `D-028`). Runtime-зависимости — SDK MAX
и драйвер `pg`; TypeScript, Vitest и `embedded-postgres` нужны для разработки.
package-lock фиксирует зависимости, образы node и postgres закреплены digest.

## Данные, надёжность и интеграции

Все сообщения деморежима помечены ДЕМО, консольная доставка — [MOCKED: MAX delivery],
в календарном файле события деморежима начинаются с [ДЕМО]. Загрузка файла через
POST /uploads проверена на настоящем MAX 23.09 (без отправки пользователю); кнопки
link и clipboard — возможности MAX, текст вопроса и ссылка дублируются в сообщении
на случай, если клиент их не поддерживает.
В нём вводятся только синтетические данные. Нет подключений МВД, Госуслуг, реестров,
ИС КФУ; публикация официальной ссылки не является интеграцией. Отметка — слова
пользователя, не подтверждение органа или сотрудника.

| Интеграция | Сейчас | Что нужно для реальной |
|---|---|---|
| Доставка сообщений MAX | реальная при TRANSPORT=max; локально — [MOCKED: MAX delivery] в консоли | — |
| Нормативный справочник | approved командой 19.10.2026 по сверке с ФЗ-115, 162-ФЗ, КоАП, ГК и Приказом МВД № 288 ([docs/legal-review.md](docs/legal-review.md)); юрист не привлекался (D-044) | независимая юридическая вычитка; ответ по въехавшим до 01.09.2026 (вопрос 2) |
| Нормы «Изменились обстоятельства» | draft по сверке 21.10.2026 ([docs/legal-review.md](docs/legal-review.md), 7); рабочие дни — пятидневка и федеральный календарь, дни Татарстана не учтены (`TBD`) | вычитка командой или юристом; региональные нерабочие дни Татарстана |
| КФУ (запись, статус документов) | нет; только ссылка на страницу и готовый вопрос, который пользователь отправляет сам | согласованный с КФУ канал обращений и владелец процесса |
| МВД, Госуслуги, реестры | нет и не планируется в MVP; прохождение процедуры — самоотметка | официальный API с правовым основанием обмена |
| Часы в demo:check | [MOCKED] зафиксированы на 24.09.2026 для повторяемости | — |
| Стартовые данные мини-приложения | реальная проверка подписи при наличии токена; локально `?demo=<id>` и [MOCKED: mini app launch data] в логе, баннер в интерфейсе | токен бота на сервере; запуск из MAX (вне MAX подписи не существует) |

Повторы входящего события не меняют состояние второй раз; чужие и устаревшие
кнопки отклоняются. Состояние и ответ сохраняются транзакционно до ответа webhook.
При сбое хранения — 503, неверном JSON — 400, отсутствии секрета — 401, теле
больше 64 KiB — 413. Групповые сообщения игнорируются, ответы направляются лично.

Очередь переживает перезапуск, повторяет отправку до 8 попыток с задержками, затем
оставляет failed. /health показывает счётчики; failed > 0 требует разбора оператором.
Старые неотправленные экраны заменяются новым актуальным ответом. После изменения
версии правил старые расчёты и напоминания останавливаются; /delete позволяет
начать новый профиль. История не переносится автоматически.

Запускается один процесс бота; несколько реплик не поддерживаются: ключ билетов на `.ics` у
каждого процесса свой, а медленная отправка может пережить аренду задания. При неопределённом результате внешнего запроса возможен дубль
сообщения; exactly-once доставка не обещается. /stop и удаление отменяют ожидающие
задания, но уже начатый сетевой запрос может завершиться.

Сохраняются MAX ID, язык, даты, самоотметки, версия правил и очередь. Сырые входящие
сообщения, паспорта и сканы не хранятся. Отдельно ведутся обезличенные счётчики воронки
(`src/bot/funnel.ts`, `D-019`): только число событий за день по вузу — начали, дошли до
плана, включили напоминания, получили и открыли напоминание, собрали комплект, отметили процедуру, открыли
помощь, удалили профиль. MAX ID, гражданство и даты в них не попадают, поэтому /delete
их не затрагивает; хранятся 400 дней. Отчёт оператора: `npm run funnel` локально или
`docker compose exec bot node dist/report.js` в контейнере. Это суммы событий, а не
люди, и отметка «пройдено» — со слов пользователя. Сводка для международного отдела вуза —
`npm run office -- <вуз>` (`docker compose exec bot node dist/office.js kfu`): профили с планом,
включённые напоминания, сроки на неделе и просроченные без отметки, запланированные визиты, открытые
«Не получилось»; только количества, числа меньше 3 скрыты (D-042). Профиль удаляется по /delete или после 400
дней без действий; если человек не дошёл до согласия (шаги выбора языка и согласия) — через 7 дней (D-048). Отпечатки событий и завершённые задания хранятся до 7 дней после
соответствующей технической даты. Подтверждение удаления может оставаться в очереди
до очистки. Локальное удаление не удаляет сообщения из MAX. До пилота определить
оператора данных, основание обработки, размещение, резервное копирование и удаление
из резервных копий. Все нормативные записи требуют независимой вычитки.

## Проверки

Устаревание данных ловит `npm run sources:check`: скачивает каждую официальную страницу, на
которой стоят нормы и профили вузов (`src/data/sources.json`), и проверяет, что дословные цитаты
(«в течение тридцати календарных дней со дня въезда», «следующего рабочего дня … после заселения в
общежитие») на месте. Пропала цитата — код выхода 1 и список, что сверить. Запускается руками
перед вехой и финалом; workflow `sources.yml` выключен вместе с остальными Actions (D-038, D-062).

```sh
npm test
npm run typecheck
npm run build
npm run demo:check
npm run web:install
npm run web:typecheck
npm run lint                     # ESLint: бот, тесты и мини-приложение; после web:install
npm run web:build
npx playwright install chromium   # один раз
npm run e2e                      # мини-приложение: Playwright, мост MAX подменён, APP_MODE=demo
docker compose config -q
```

Собственного API у решения нет (D-033): `/webhook` принимает события MAX, `/api/*` —
внутренний бэкенд мини-приложения. openapi.yaml и DATA-API.yaml описывают эти границы
для справки; синтетические примеры — fixtures/.

## Остановка и повторный запуск

```sh
docker compose down
docker compose up -d
```

Именованный том сохраняет данные. Не добавлять -v, если данные нужны.
Локальный Node останавливается Ctrl+C с ожиданием текущей отправки.
Бэкап — `pg_dump` с проверкой восстановления в отдельной БД (docs/deploy.md); там же
разовый перенос прежней SQLite.
Мониторинг: основной — внешний keyword-монитор UptimeRobot на /health раз в 5 минут с
письмом команде (D-049; включает человек, docs/deploy.md, «Мониторинг»). Второй слой —
`scripts/monitor.sh` руками: /health, failed-задания и — с `MAX_BOT_TOKEN` в окружении —
наличие подписки MAX (D-032). Workflow `monitor.yml` выключен: GitHub Actions не используем (D-062).
