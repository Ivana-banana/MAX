**Первые 90 дней — подготовка иностранного студента к обязательным процедурам**

Бот показывает план, чек-лист документов и напоминания. Целевой пилот: совершеннолетний
иностранный первокурсник, первый въезд с 01.09.2026 для учёбы более чем на 90 дней,
общежитие КФУ, без РВП/РВПО/ВНЖ и ранее пройденных процедур. КФУ — кандидат, не партнёр.

**Статус:** бот развёрнут в MAX в демо-режиме (APP_MODE=demo, все сообщения помечены
ДЕМО): [max.ru/t149_hakaton_max_bot](https://max.ru/t149_hakaton_max_bot), проверка
живости — https://81-26-178-75.sslip.io/health. Ручной прогон 23.09: мобильный MAX —
основной путь пройден, веб-версия ещё не пройдена (docs/verification-2026-09-23.md). Все нормативные правила — draft; APP_MODE=live их блокирует.
Версия не готова к сдаче. Развёртывание — [docs/deploy.md](docs/deploy.md).

**Запуск одной командой**

```sh
docker compose up --build -d
```

Нужны Docker Engine, Compose v2, сеть для Docker Hub и npm при сборке. На хосте порт
3000 привязан к 127.0.0.1; внутри контейнера также 3000. Другой порт:
`BOT_PORT=3300 docker compose up --build -d`.

```sh
curl http://127.0.0.1:3000/health
docker compose logs --tail=30 bot
docker compose run --rm --no-deps bot node dist/demo.js --script
```

Последняя команда проходит синтетический сценарий на отдельной БД в памяти,
с явно обозначенной учебной датой 24.09.2026; проверяет одно напоминание, отметку
о прохождении и остановку уведомлений. Профили сервера она не меняет.

Без Docker: Node.js 24+, `npm ci --ignore-scripts`, `npm run build`,
`npm run demo` — интерактивный терминал, `npm run demo:check` — сценарий,
`npm start` — HTTP-сервер. Терминал хранит отдельный учебный профиль в
data/terminal-demo.sqlite; /exit закрывает сеанс, /delete удаляет профиль.

**Основной сценарий и проверка**

1. /start → русский или English → условия хранения данных.
2. Подтвердить границы пилота. «Нет / не уверен» выводит контакт КФУ без расчёта.
3. Выбрать гражданство и ввести дату въезда ГГГГ-ММ-ДД. Неверную дату можно исправить.
4. Получить план двух процедур: медосвидетельствование и дактилоскопия.
   Миграционный учёт оформляется отдельно через университет.
5. Открыть карточку, отметить документы; посмотреть источник и дату сверки;
   кнопка «Открыть норму» ведёт на текст закона.
6. Включить напоминания: за 7, 3 и 1 день, в 09:00 по Москве. Если включить
   позднее 09:00 в соответствующий день, сообщение уйдёт при обработке очереди.
   «Подробнее» в напоминании открывает карточку, даже если после него были другие действия.
   «📅 Добавить сроки в календарь» присылает файл first-90-days.ics: события на даты
   сроков с напоминаниями календаря в те же дни и час — работают и при выключенных
   уведомлениях бота. Повторная выгрузка обновляет события, а не дублирует.
7. «Процедура пройдена» → фактическая дата. Для повтора отдельно показываются
   рекомендуемая дата и окончание расчётного окна.
8. «Не получилось» в карточке собирает готовый вопрос КФУ с названием процедуры,
   расчётным сроком, гражданством и датой въезда; кнопка «Скопировать вопрос» кладёт
   его в буфер, «Открыть страницу КФУ» — ведёт на контакты. Отправляет пользователь сам.
   /stop выключает напоминания; /delete запрашивает подтверждение удаления.

Вуз выбирается ссылкой: max.ru/t149_hakaton_max_bot?start=itmo открывает демо-профиль ИТМО
(ИТМО не партнёр), без параметра — КФУ. Вручную то же: `/start itmo` до ввода даты. Профиль
вуза — файл в src/data/universities: название, страница контактов, кнопки гражданств;
новый вуз добавляется файлом без правок кода. Если клиент MAX сообщил язык ru или en,
вопрос о языке пропускается, переключиться можно кнопкой. В плане, карточке и напоминании
показано «осталось N дней»; после расчётной даты карточка говорит, что срок прошёл,
и готовит вопрос вузу — без оценки последствий.

Синтетический KZ, въезд 01.09.2026: даты 30.09.2026 и 29.11.2026 (день въезда входит в
срок до ответа юриста — D-016).
Медпроцедура 20.09.2026: рекомендуемая дата 20.09.2027, конец окна 20.10.2027.
Это примеры формул draft-справочника, не подтверждённые юридические рекомендации.
BY и въезд до сентября не получают нормативного плана.

**Окружение**

Для локального демо .env не нужен. .env.example содержит демонстрационные значения.
Секреты помещаются только в исключённый из Git файл .env.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| APP_MODE | demo | demo или live; live требует approved-правил |
| TRANSPORT | console | console или max |
| MAX_BOT_TOKEN | пусто | для max |
| WEBHOOK_SECRET | публичное локальное демозначение | для max нужен собственный секрет 32–256 букв, цифр, _ и - |
| BOT_PORT | 3000 | порт Compose на хосте |
| PORT / HOST | 3000 / 127.0.0.1 | прямой запуск; Docker задаёт HOST=0.0.0.0 |
| DB_PATH | ./data/bot.sqlite | Compose использует /app/data/bot.sqlite |
| RULES_PATH | ./src/data/rules/ru-student.json | путь к справочнику |
| WEBHOOK_URL | пусто | https://ваш-домен/webhook для регистрации |
| UNIVERSITIES_PATH | ./src/data/universities | каталог профилей вузов (JSON) |
| DEFAULT_UNIVERSITY | kfu | профиль для входа без диплинка |

Для изменения DB_PATH/HOST/RULES_PATH в контейнере используйте Compose override.
DEBUG при max запрещён: SDK-диагностика может содержать персональные сведения.

**Реальная интеграция MAX**

Нужны бот с токеном, HTTPS на 443 с доверенным сертификатом и reverse proxy на
локальный порт. Эти внешние условия Docker не заменяет.

1. Согласовать владельца токена: один активный потребитель.
2. Установить в .env TRANSPORT=max, токен, собственный WEBHOOK_SECRET и WEBHOOK_URL.
   APP_MODE=demo подходит только для явно обозначенного учебного показа.
3. Запустить сервис, настроить HTTPS и проверить /health извне.
4. После запуска вручную создать подписку MAX: в Docker —
   `docker compose run --rm --no-deps bot node dist/subscribe.js`, без Docker —
   `npm run subscribe`. Скрипт отказывается заменять существующие подписки.
5. Пройти путь в мобильном и веб-MAX и записать коммит, дату, результат.

Используется официальный @maxhub/max-bot-api 0.3.1, домен platform-api2.max.ru,
Authorization header. Сертификат platform-api2.max.ru выпущен Russian Trusted Root CA
(Минцифры), которого нет в хранилище Node: без него бот принимает webhook, но не может
ответить (UNABLE_TO_GET_ISSUER_CERT_LOCALLY). Корневой сертификат лежит в
certs/russian_trusted_root_ca.pem (SHA-256 D2:6D:…:CF:31, проверяется тестом), Docker-образ
подключает его через NODE_EXTRA_CA_CERTS. Без Docker переменную задают в окружении
процесса: `NODE_EXTRA_CA_CERTS=certs/russian_trusted_root_ca.pem npm start` — из .env
(--env-file) Node её не читает. TLS-проверку не отключать.
[Документация API](https://dev.max.ru/docs/chatbots/bots-coding/prepare),
[требования webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions).

**Состав и архитектура**

Один процесс: HTTP webhook → транзакция SQLite (профиль + отпечаток события +
ответ в очереди) → фоновая отправка. src/core считает даты, src/data валидирует
правила, src/bot содержит диалог, БД, транспорт и HTTP, src/main.ts запускает сервис.
SQLite встроен в Node.js (node:sqlite); SDK MAX — единственная прямая runtime-зависимость.
TypeScript и Vitest нужны для разработки. package-lock фиксирует зависимости,
базовый Docker-образ закреплён digest. Мини-приложение и отдельная СУБД не требуются.

**Данные, надёжность и интеграции**

Все сообщения деморежима помечены ДЕМО, консольная доставка — [MOCKED: MAX delivery],
в календарном файле события деморежима начинаются с [ДЕМО]. Загрузка файла через
POST /uploads проверена на настоящем MAX 23.09 (без отправки пользователю); кнопки
link и clipboard — возможности MAX, текст вопроса и ссылка дублируются в сообщении
на случай, если клиент их не поддерживает.
В нём вводятся только синтетические данные. Нет подключений МВД, Госуслуг, реестров,
ИС КФУ; публикация официальной ссылки не является интеграцией. Отметка — слова
пользователя, не подтверждение органа или сотрудника.

| Интеграция | Сейчас | Что нужно для реальной |
|---|---|---|
| Доставка сообщений MAX | реальная при TRANSPORT=max; локально — [MOCKED: MAX delivery] в консоли | — |
| Нормативный справочник | draft: сроки сверены с текстом ФЗ-115 и 162-ФЗ ([docs/legal-review.md](docs/legal-review.md)), юристом не утверждены; live заблокирован | независимая юридическая вычитка, status approved и reviewedBy у каждой нормы |
| КФУ (запись, статус документов) | нет; только ссылка на страницу и готовый вопрос, который пользователь отправляет сам | согласованный с КФУ канал обращений и владелец процесса |
| МВД, Госуслуги, реестры | нет и не планируется в MVP; прохождение процедуры — самоотметка | официальный API с правовым основанием обмена |
| Часы в demo:check | [MOCKED] зафиксированы на 24.09.2026 для повторяемости | — |

Повторы входящего события не меняют состояние второй раз; чужие и устаревшие
кнопки отклоняются. Состояние и ответ сохраняются транзакционно до ответа webhook.
При сбое хранения — 503, неверном JSON — 400, отсутствии секрета — 401, теле
больше 64 KiB — 413. Групповые сообщения игнорируются, ответы направляются лично.

Очередь переживает перезапуск, повторяет отправку до 8 попыток с задержками, затем
оставляет failed. /health показывает счётчики; failed > 0 требует разбора оператором.
Старые неотправленные экраны заменяются новым актуальным ответом. После изменения
версии правил старые расчёты и напоминания останавливаются; /delete позволяет
начать новый профиль. История не переносится автоматически.

Работать должен **один процесс на одну БД**. Масштабирование несколькими репликами
не поддерживается. При неопределённом результате внешнего запроса возможен дубль
сообщения; exactly-once доставка не обещается. /stop и удаление отменяют ожидающие
задания, но уже начатый сетевой запрос может завершиться.

Сохраняются MAX ID, язык, даты, самоотметки, версия правил и очередь. Сырые входящие
сообщения, паспорта и сканы не хранятся. Отдельно ведутся обезличенные счётчики воронки
(`src/bot/funnel.ts`, `D-019`): только число событий за день по вузу — начали, дошли до
плана, получили и открыли напоминание, собрали комплект, отметили процедуру, открыли
помощь, удалили профиль. MAX ID, гражданство и даты в них не попадают, поэтому /delete
их не затрагивает; хранятся 400 дней. Отчёт оператора: `npm run funnel` локально или
`docker compose exec bot node dist/report.js` в контейнере. Это суммы событий, а не
люди, и отметка «пройдено» — со слов пользователя. Профиль удаляется по /delete или после 400
дней без действий. Отпечатки событий и завершённые задания хранятся до 7 дней после
соответствующей технической даты. Подтверждение удаления может оставаться в очереди
до очистки. Локальное удаление не удаляет сообщения из MAX. До пилота определить
оператора данных, основание обработки, размещение, резервное копирование и удаление
из резервных копий. Все нормативные записи требуют независимой вычитки.

**Остановка и повторный запуск**

```sh
docker compose down
docker compose up -d
```

Именованный том сохраняет данные. Не добавлять -v, если данные нужны.
Локальный Node останавливается Ctrl+C с ожиданием текущей отправки.
Бэкап делать SQLite backup или при остановленном процессе с учётом WAL.
Мониторить HTTPS, /health, failed-задания и наличие подписки MAX.
