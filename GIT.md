# GIT.md — правила ведения Git

Цель: `main` в любой момент — рабочий кандидат на сдачу, а сданную версию можно
однозначно восстановить (условия требуют зафиксированный commit hash, после дедлайна
код не меняется).

Правило: **закончил одно логическое действие — проверь, закоммить и запушь.**

## Автономность агента

Агент коммитит и пушит **сам, без запроса подтверждения**, как только шаг закончен и
проверки зелёные. Это постоянное разрешение на проект; технически оно задано в
`.claude/settings.json` (`permissions.allow`), а `permissions.deny` закрывает всё,
что переписывает историю или сгребает чужую работу.

Разрешение опирается на проверки, а не отменяет их:

- перед коммитом и push — `git fetch --prune` и просмотр обеих сторон расхождения;
- в коммит попадает только текущий шаг: `git add <явные пути>`. Никогда `git add -A`,
  `git add .`, `git commit -a` — в дереве может лежать незакоммиченная работа другого
  участника или другой сессии;
- push только fast-forward. Отклонён — `git fetch`, разобраться с чужими коммитами,
  свести merge'ем и сообщить; не форсить и не оставлять коммиты локально молча;
- `--force`, `rebase` и `amend` опубликованного, `reset --hard`, `clean` — только по
  явной просьбе человека. Удаление веток и worktree агент делает сам, но только по
  правилам из «Уборка»;
- секреты, `.env`, `node_modules`, сборки и логи не коммитятся (см. `.gitignore` и
  Stop-хук `check-secrets.sh`).

## Задачи (GitHub Issues)

Доска — [GitHub Issues](https://github.com/M1hairu/MAX_GOATed_messenger/issues), клиент —
`scripts/issues.sh` (`gh` + `jq`). С 19.10.2026 вместо таблицы в `HANDOFF.md` (#18).

```bash
bash scripts/issues.sh free [метка]     # свободные задачи; метка, например P0 или area:bot
bash scripts/issues.sh take <N>         # взять: назначает на тебя
bash scripts/issues.sh mine             # мои открытые
bash scripts/issues.sh note <N> <текст> # итог, вопрос соседу, где остановился
bash scripts/issues.sh create <заголовок> <метки> <файл|->   # шаблон — .github/ISSUE_TEMPLATE/task.md
```

- **Без взятой задачи файлы не меняем и не коммитим.** Ветка — `worktree-<N>-<тема>`,
  задача #N открыта и назначена на тебя. Это проверяет PreToolUse-хук `check-issue.sh`.
- Нашёл погрешность, которую не чинишь сейчас, — сразу issue, а не заметка в чате.
- Занятая `area:` не держит: `take` предупреждает, договориться в задаче (`note`).
- Чужая задача без движения дольше `TAKEOVER_MIN` минут (по умолчанию сутки) —
  `take` перехватывает её с комментарием и продолжает её ветку. Прямая просьба
  человека «возьми #N» — `take <N> --human`.
- Задача, которую агент не сделает (права, люди, MAX руками), — метка `needs-human`.
- Коммит ссылается на задачу: `<поток>: <что закончено> (#N)`; последний коммит
  задачи — `Closes #N` в теле, или закрыть задачу с комментарием о проверке.

## Git-хуки (для людей и Codex)

Хуки Claude Code (`.claude/hooks/`) видят только Claude Code. Для всех остальных, кто
коммитит, есть git-хуки в `.githooks/`. Подключить один раз в клоне:

```bash
git config core.hooksPath .githooks
```

- `pre-commit` — секреты в индексе (`.claude/hooks/check-secrets.sh --git`), затем
  `scripts/issues.sh check .`: коммит только в worktree взятой задачи.
- `pre-push` — `scripts/issues.sh check .`. Push, который только удаляет ветки (уборка),
  не проверяется.
- Обход `--no-verify` — только по явной просьбе человека.
- Проверка хуков без сети: `bash .claude/hooks/test-hooks.sh`.

## Worktree по умолчанию

Основная копия (клон репозитория на ветке `main`; путь у каждого свой, ниже —
`<основная копия>`) — не рабочее место агента. В ней могут параллельно сидеть человек
и другие сессии, и незаконченная правка одного ломает запуск и тесты остальным.
Поэтому **любая задача, меняющая файлы, делается в своём worktree на своей ветке**, а
в `main` попадает только проверенный результат.

Старт:

```bash
# Claude Code — сессия сразу открывается в .claude/worktrees/<N>-<тема>
# на ветке worktree-<N>-<тема>
claude -w <N>-<тема>

# Уже запущенная сессия или другой агент (Codex и т. п.) — те же путь и ветка руками:
git fetch --prune
git worktree add .claude/worktrees/<N>-<тема> -b worktree-<N>-<тема> origin/main
```

`.claude/worktrees/` в `.gitignore`. `claude -w` сам копирует `.env` из основной копии
(список — `.worktreeinclude`; проверено 15.09). При `git worktree add` руками `.env`
копировать самому. `node_modules` и `.venv` в новом worktree нет — поставить заново.

То же и в обратную сторону: **после `pull`, который принёс новые или изменённые
зависимости, в основной копии нужен `npm install`** — иначе Stop-хук `check-tests.sh`
покажет `vitest: command not found` и красные тесты на ровном месте. `node_modules`
не коммитится и между копиями не переносится.

Финиш — в `main` вливаем **из worktree, не переключая основную копию**. Всё ниже
делает `bash scripts/finish.sh` (из worktree, всё закоммичено): fetch, merge, четыре
проверки, push ветки, `push HEAD:main`, закрытие задачи, pull в основной копии, уборка.
Перед запуском покажи ветку свежему агенту `reviewer`. Вручную — те же шаги:

```bash
# 1. проверки зелёные, коммит только своих путей
git fetch --prune
git merge origin/main              # если main ушёл вперёд; после merge — тесты заново
git push -u origin HEAD            # ветка на сервере — резервная копия
git push origin HEAD:main          # только fast-forward: если main ушёл, push отклонится
# 2. в основной копии, когда там никто не работает:
git -C <основная копия> pull --ff-only
# 3. уборка — см. ниже
```

### Уборка

Агент убирает за собой сам, человеку ничего вручную делать не нужно. Ветку или
worktree можно удалить, только если **оба** условия выполнены (так удаление ничего не
теряет):

1. в ветке нет коммитов, которых нет в `origin/main`:
   `git fetch --prune && git rev-list --count origin/main..<ветка>` → `0`;
2. ветка не открыта ни в одном worktree, кроме твоего собственного, а в твоём нет
   незакоммиченного: `git worktree list`, `git -C <путь> status --porcelain` → пусто.
   Worktree другой сессии не удаляется, даже чистый и «пустой»: сессия могла только
   начать работу.

```bash
git worktree remove .claude/worktrees/<N>-<тема>   # без --force
git branch -D worktree-<N>-<тема>                  # после проверки п. 1
git push origin --delete worktree-<N>-<тема>
git worktree prune
```

Свой worktree убирать из основной копии (`git -C <основная копия> …`), а не изнутри
него. Чужой worktree с незакоммиченными изменениями или ветку с невлитыми коммитами не
трогать никогда — даже если она выглядит заброшенной: спросить человека. `main`
удалить нельзя (`permissions.deny`).

Без worktree, прямо в основной копии, можно только:

- чтение, анализ, запуск тестов и `jury` без правок;
- строка «Токен бота» в `HANDOFF.md`, когда меняется держатель токена;
- срочный однострочный фикс сломанного `main`, если человек прямо попросил.

Крупное или рискованное (общие контракты, сценарий в MAX, Docker, `.claude/`) — ветку
не вливать в `main` самому: запушить ветку и попросить ревью.

## Перед началом работы

```bash
git fetch --prune
git status -sb
git log --oneline HEAD..origin/main   # что пришло от команды
git log --oneline origin/main..HEAD   # что есть только у нас
```

Если чужой коммит пересекается с задачей — сначала прочитать diff. Перед тем как
назвать что-то дефектом, убедиться, что ветка не `behind`.

## Коммиты

Формат: `<поток>: <что закончено> (#N)`, сообщение на русском.

| Префикс | Поток |
|---|---|
| `bot:` | чат-бот: сценарии, обработчики, клавиатуры |
| `app:` | мини-приложение: экраны, MAX Bridge, MAX UI |
| `api:` | бэкенд, интеграции, данные, моки |
| `product:` | `docs/product/`: проблема, CJM, гипотезы, масштабирование, пилот |
| `pitch:` | презентация, демо, скриншоты |
| `infra:` | Docker, CI, зависимости, настройки Claude Code, Git |
| `docs:` | README, условия, решения, справки |
| `fix:` | исправление, если поток смешанный |

Один коммит — один осмысленный шаг. Трейлеры соавторства ИИ (`Co-Authored-By`,
`Claude-Session`, «Generated with Claude Code») в коммиты и PR не добавляем.

## Ветки и ревью

- `main` — запускается, тесты зелёные, основной сценарий не сломан. Прямых коммитов
  в `main` нет (исключения — в «Worktree по умолчанию»).
- Ветка задачи — `worktree-<N>-<тема>`; крупная или рискованная — ревью другим
  участником до вливания.
- Force-push в `main` запрещён.

## Ремоуты

`origin` — `https://github.com/M1hairu/MAX_GOATed_messenger.git`. Второй ремоут не
выдумывать: если организаторы выдадут свой репозиторий, добавить его и описать схему
здесь. Проверка, что commit действительно на сервере:

```bash
git rev-parse HEAD
git ls-remote origin main
```

## Сдача и теги

Сданную версию тегировать **после** проверки по скиллу `submission-checklist`:

```bash
git tag -a submit-online -m "Онлайн-этап: <commit>, сценарий пройден в MAX <дата>"
git push origin submit-online
```

Commit hash из тега идёт на первый слайд презентации. Не ставить тег заранее.

## Безопасный откат

| Ситуация | Действие |
|---|---|
| Посмотреть историю | `git log --oneline --decorate --graph` |
| Вернуть свой файл | `git restore <path>` после просмотра diff |
| Отменить опубликованный коммит | `git revert <hash>` |
| Посмотреть старое состояние | `git switch --detach <tag-or-hash>` |
