# Чек-лист сдачи

Источник — раздел «Формат сдачи» и «Ограничения» в `Забота о людях.md`. Каждый пункт
проверяется **командой или файлом**, а не памятью. Результат — таблица
`пункт | ✅/❌/⚠️ | доказательство | что сделать`. Ничего не исправлять молча: сначала
отчёт, исправления — отдельными коммитами.

## 0. Состояние git

```bash
git fetch --prune && git status -sb     # чисто, не behind
git rev-parse HEAD && git ls-remote origin main   # commit есть на сервере
```

## 1. Работающее решение в MAX

- Ссылка на бота или мини-приложение есть в README и на первом слайде.
- Основной сценарий пройден руками **сегодня** на этом commit — в мобильной и в
  веб-версии MAX. Нет записи о прогоне — ⚠️, а не ✅.
- Мини-приложение открывается через бота, работает по HTTPS.

## 2. Зафиксированная версия

- Commit hash, который пойдёт в сдачу, записан; тег ставится после этого чек-листа
  (`GIT.md`, «Сдача и теги»).

## 3. README.md — все пункты

Проверить наличие каждого раздела (grep по заголовкам и чтение):

- [ ] назначение решения
- [ ] основной пользовательский сценарий
- [ ] состав и архитектура
- [ ] **одна команда** запуска всех локальных компонентов через Docker
- [ ] необходимые параметры окружения
- [ ] переменные окружения
- [ ] используемые порты
- [ ] зависимости
- [ ] внешние сервисы и интеграции
- [ ] описание работы с данными
- [ ] порядок работы с тестовыми данными
- [ ] пошаговый сценарий проверки
- [ ] примеры ожидаемого поведения системы
- [ ] известные ограничения
- [ ] порядок остановки и повторного запуска
- [ ] внешний сервис, не воспроизводимый в Docker: назначение и условия проверки
- [ ] список моделируемых интеграций (`[MOCKED]`) и что нужно для реальных

## 4. Файл зависимостей

`package-lock.json` / `pnpm-lock.yaml` / `uv.lock` / `requirements.txt` с версиями
закоммичен и соответствует манифесту.

## 5. Docker

```bash
ls Dockerfile* */Dockerfile* compose.yaml docker-compose.yml .dockerignore .env.example 2>/dev/null
docker compose config -q                       # конфиг валиден
docker compose pull --ignore-buildable         # базовые образы не входят в лимит
time docker compose build --no-cache           # ≤ 5 минут
docker compose up -d && docker compose ps      # всё поднялось
docker compose down
```

- Сборку мерить на **чистом клоне** (`git clone <origin> /tmp/check && cd /tmp/check`),
  чтобы не опираться на локальные файлы вне git.
- `.dockerignore` исключает `node_modules`, `.git`, `.env`.
- В Dockerfile нет лишних тяжёлых шагов.

## 6. Секреты

```bash
bash .claude/hooks/check-secrets.sh            # пустой вывод = чисто
git log -p | grep -i -E 'token|secret|api[_-]?key' | head   # не утекало ли в истории
```

`.env.example` — только плейсхолдеры. Секрет, найденный в истории, — ❌ с пометкой:
токен нужно перевыпустить, удаление файла его не отзывает.

## 7. Презентация (PDF)

Первый слайд (служебный):

- [ ] ссылка на бота или мини-приложение в MAX
- [ ] ссылка на Git-репозиторий и commit hash
- [ ] адрес собственного API, если есть
- [ ] тестовые логины и пароли
- [ ] токены, ключи и переменные окружения, нужные для проверки
- [ ] краткий порядок прохождения основного сценария

Со второго слайда: название и команда; executive summary; ЦА, проблема и актуальность;
решение и сценарий; ожидаемый эффект; архитектура; данные и интеграции; масштабирование
и условия адаптации; ограничения, риски и допущения; источники.

## 8. Только если есть собственный API

- [ ] HTTPS-адрес, доступный весь период проверки
- [ ] `openapi.yaml` / `openapi.json` (OpenAPI 3.0 или 3.1)
- [ ] тестовые учётные записи по ролям
- [ ] тестовые данные (JSON/CSV)
- [ ] `DATA-API.yaml`: версия конфигурации, название или идентификатор команды,
      базовый адрес, обязательные проверки, метод + путь, параметры, роль, ожидаемые
      статус-коды, формат ответа

Собственный API баллов не добавляет. Если его нет — раздел пропустить.

## 9. Ограничения трека

- [ ] Тема и проблема соответствуют треку, актуальность обоснована источниками
- [ ] Нет закрытых библиотек и кода без свободной лицензии (проверить лицензии зависимостей)
- [ ] Медицинские и юридические ответы не выдают себя за решение специалиста или ведомства
- [ ] Реальных персональных и медицинских данных в репозитории нет
