# MVP

Сведено 16.09.2026 (`D-010`). Статус: дизайн; кода, токена и прогонов в MAX нет.
Рабочее обозначение — «Первые 90 дней»; ник бота генерирует платформа, название и
карточка ещё не выбраны.

MVP — минимальная версия, в которой пользователь полностью получает основной
результат: **свои календарные даты по каждой обязательной процедуре, комплект
документов к каждой и напоминания перед сроками**.

## Основной сценарий

| № | Шаг | Что видит пользователь | Где |
|---|---|---|---|
| 1 | Вход | Что бот делает, чего не делает (не юрист, не подаёт документы), выбор языка: русский / English | чат |
| 2 | Гражданство | Кнопки с частыми странами + «другая»; отдельная ветка для Беларуси (исключение по закону) | чат |
| 3 | Дата въезда | Ввод даты; проверка: не в будущем, не абсурдно давно, понятная ошибка при неверном формате | чат |
| 4 | Вуз и жильё | КФУ и общежитие в MVP; частное жильё и нестандартный статус — явный выход к официальной инструкции с объяснением границы | чат |
| 5 | Что уже пройдено | Чек-лист процедур: миграционный учёт / медосвидетельствование / дактилоскопия и фото | чат |
| 6 | **План** | Список процедур: название, **конкретная дата**, «осталось N дней», статус (просрочено / срочно / есть время) | чат |
| 7 | Карточка процедуры | Что сделать, **чек-лист документов с отметками**, чего не хватает, куда идти, **основание: норма + ссылка + дата сверки** | чат, обзор целиком — мини-приложение |
| 8 | Напоминания | За 7, 3 и 1 день до каждой даты: сообщение с кнопками «Сделано» и «Подробнее», открывающее **именно незавершённый шаг** | чат |
| 9 | «Сделано» | План пересчитывается; для медосвидетельствования сразу ставится срок повтора через год | чат |

Результат виден в конце шага 6, уточняется на шаге 7 и подтверждается первым
напоминанием — сценарий заканчивается не сообщением, а изменением состояния.

**Почему так поделено.** Чат — вход, последовательные вопросы, статусы и возвращение к
действию: по условиям (стр. 15) это его зона. Мини-приложение — одновременный обзор
всех процедур и редактирование отметок, то есть список и сравнение. **Чат-сценарий
самодостаточен:** мини-приложение улучшает шаг 7, но без него результат достижим —
иначе web-версия и любой сбой Bridge ломали бы допуск.

Состояния для каждого действия: загрузка, результат, ошибка с повтором. Ошибка не
роняет диалог — пользователь остаётся на своём шаге. Состояние общее между мобильным
MAX и web. Кнопка «Не уверен» ведёт к конкретному официальному контакту и памятке
вопросов.

## MoSCoW

| MoSCoW | Функция | Почему здесь |
|---|---|---|
| Must Have | Диалог сбора данных (шаги 1–5), одна утверждённая ветка | без входных данных нет расчёта |
| Must Have | Справочник норм: срок, основание, ссылка, дата сверки | ядро ценности; единственное, что отличает нас от памятки |
| Must Have | Расчёт персональных дат от даты въезда | собственно результат |
| Must Have | План и карточка процедуры с чек-листом и основанием | без основания продукт — ещё один противоречивый источник |
| Must Have | Напоминания по расписанию и отметка «сделано» | без них это справочник, а не сопровождение |
| Must Have | Работа в мобильном MAX и в web, серверная проверка `initData` | допуск и достоверность |
| Must Have | Состояния загрузки / результата / ошибки, валидация даты, восстановление | критерий UX и стабильности |
| Must Have | Русский и английский | пользователь по определению не носитель языка |
| Must Have | Воспроизводимая сдача: README, Docker, lock-файл | без этого допуск и техкритерии не закрыть |
| Should Have | Мини-приложение: обзор всех процедур и отметки в одном экране | усиливает шаг 7; кандидат на доказательство переноса |
| Should Have | Геолокация → ближайшее подразделение МВД и уполномоченная клиника | кандидат на бонус; ценность только если адреса реальные |
| Should Have | Второй вуз на тех же данных | доказательство масштабирования на защите |
| Could Have | Кабинет сотрудника вуза с проверкой комплектности | только при реальном участнике пилота и основании обработки |
| Could Have | Ещё языки сверх ru/en | **сделано:** узбекский и китайский (`D-024`); язык — файл в `src/data/i18n/` плюс переводы названий (`D-020`) |
| **Won't Have** | Запись в клинику, подача документов в МВД, получение статуса из «Госуслуг» | нет разрешённой интеграции; имитировать подачу опасно |
| **Won't Have** | Статус заявления в МВД | нет доступа; выдумывать статус недопустимо |
| **Won't Have** | Юридические заключения, разбор личных ситуаций, LLM-ответы по нормативке | цена ошибки — правовой статус человека; отвечаем только из справочника |
| **Won't Have** | Хранение медицинских данных и паспортного архива | 152-ФЗ; храним только факт «пройдено / не пройдено» |
| **Won't Have** | Распознавание документов, OCR паспорта | не нужно для результата, повышает риск ПДн |
| **Won't Have** | Все миграционные ситуации; трудовые мигранты и патенты | следующий сегмент масштабирования, не MVP |

Даже при неограниченном времени эти границы сохраняют измеримость ценности. Глубина
идёт в исключения, доступность, источники, восстановление и реальный пилот.

## Данные и интеграции

| Данные / канал | Режим | Источник, дата, территория | Что нужно для реального |
|---|---|---|---|
| Нормативные сроки процедур | **Реальные** | ФЗ-115 ст. 5 п. 13, 18–19, ред. 26.06.2026; сверка с текстом норм 23.09.2026, РФ | первоисточник; утверждение юристом — `docs/legal-review.md` |
| Перечень процедур и документов | **Реальные**, требуют вычитки | нормативка + инструкции КФУ | подтверждение владельцем процесса |
| MAX: запуск, сообщения, личность в рамках платформы | **Реальная интеграция**, пока не реализована | — | токен организаторов, HTTPS, проверка mobile/web |
| Даты и отметки пользователя | **Реальные**, вводит сам; в UI помечено «с ваших слов» | пользователь | — |
| Справочник вузов и регионов | **Тестовый**, в MVP КФУ и Казань | заполняется вручную | нет открытого API; расширяется данными, не кодом |
| Адреса подразделений МВД и уполномоченных клиник | **[MOCKED]**, помечено в UI и в логе | реестр уполномоченных клиник введён с 01.09.2026, открытость — `TBD` | открытые данные или выгрузка от ведомства |
| Контрольные профили для тестов | **Синтетические**, помечены «Демонстрационные данные» | — | никаких реальных паспортов |
| Ответ сотрудника вуза | **Отсутствует** без партнёра | — | реальный сотрудник и основания; симуляция — `[MOCKED: проверка сотрудником]` в UI, логах и материалах |
| МВД / «Госуслуги» / внутренние ИС вуза | **Не подключены** | — | не заявляем чтение статусов и отправку заявлений |

Получение официальной страницы **не является** интеграцией с реестром.

**Правило для нормативных данных:** ни один срок не берётся из знаний модели. Строка
справочника без ссылки на норму и даты сверки в продукт не попадает — это и есть
защита от того, из-за чего продукт существует. Юридическая вычитка справочника —
отдельная задача в `HANDOFF.md`, она блокирует релиз.

## Ограничения, которые честно называем

- Бот не юрист и не заменяет решение МВД; при расхождении с ведомством прав ведомство.
- Адреса пунктов в MVP — тестовые, помечены в интерфейсе и в логе как `[MOCKED]`.
- Отметка «документ есть» — со слов пользователя; она не подтверждает подлинность
  документа и не означает принятия заявления ведомством.
- Сроки действуют для типового случая «студент, въезд на срок свыше 90 дней»;
  нетиповые статусы бот не разбирает и отправляет к службе миграционного сопровождения
  вуза — ветка «надёжного ответа нет, вот куда обратиться».
- КФУ — кандидат, не подтверждённый партнёр.
