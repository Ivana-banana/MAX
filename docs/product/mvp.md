# MVP

MVP — минимальная версия, в которой пользователь полностью получает основной
результат: **свои календарные даты по каждой обязательной процедуре и напоминания
перед ними**.

## Основной сценарий

Всё в чате. Мини-приложение в Must Have не входит — по условиям (стр. 15)
последовательные вопросы, статусы и напоминания относятся к чату, а не к
мини-приложению.

| № | Шаг | Что видит пользователь |
|---|---|---|
| 1 | `/start` | Что бот делает, чего не делает (не юрист, не подаёт документы), выбор языка: русский / English |
| 2 | Гражданство | Кнопки с частыми странами + «другая»; отдельная ветка для Беларуси (исключение по закону) |
| 3 | Дата въезда | Ввод даты; проверка: не в будущем, не абсурдно давно, понятная ошибка при неверном формате |
| 4 | Вуз и регион | Список из справочника; в MVP — КФУ и Казань, остальные помечены «скоро» |
| 5 | Что уже пройдено | Чек-лист процедур: миграционный учёт / медосвидетельствование / дактилоскопия и фото |
| 6 | **План** | Список процедур: название, **конкретная дата**, «осталось N дней», статус (просрочено / срочно / есть время) |
| 7 | Карточка процедуры | Что сделать, какие документы, куда идти, **основание: норма + ссылка + дата сверки** |
| 8 | Напоминания | За 7, 3 и 1 день до каждой даты: push с кнопками «Сделано» и «Подробнее» |
| 9 | «Сделано» | План пересчитывается; для медосвидетельствования сразу ставится срок повтора через год |

Результат виден в конце шага 6 и подтверждается первым напоминанием — то есть
сценарий заканчивается не сообщением, а изменением состояния пользователя.

Состояния для каждого действия (прямой подпункт критерия UX): загрузка, результат,
ошибка. Ошибка внешнего вызова не роняет диалог — пользователь остаётся на своём шаге
и может повторить. После любой ошибки план остаётся доступен по команде.

## MoSCoW

| MoSCoW | Функция | Почему здесь |
|---|---|---|
| Must Have | Диалог сбора данных (шаги 1–5) | без входных данных нет расчёта |
| Must Have | Справочник норм со сроками, ссылкой на норму и датой сверки | это ядро ценности и единственное, что отличает нас от инструкции |
| Must Have | Расчёт персональных дат от даты въезда | собственно результат |
| Must Have | План и карточка процедуры с основанием | без основания продукт — ещё один противоречивый источник |
| Must Have | Напоминания по расписанию и отметка «сделано» | без них это справочник, а не сопровождение |
| Must Have | Русский и английский | пользователь по определению не носитель языка |
| Must Have | Состояния загрузки / результата / ошибки, валидация даты | критерий UX и стабильности |
| Should Have | Геолокация → ближайшее подразделение МВД и уполномоченная клиника | кандидат на платформенный бонус; ценность только если адреса реальные |
| Should Have | Экспорт плана одним сообщением, чтобы переслать куратору | дешёво, помогает в общежитии |
| Could Have | Мини-приложение: календарь плана | только после того, как чат-сценарий полностью работает |
| Could Have | Ещё языки сверх ru/en | тексты и так лежат в данных |
| **Won't Have** | Запись в клинику и подача документов в МВД | нет интеграции; имитировать подачу документов нечестно и опасно |
| **Won't Have** | Статус заявления в МВД | нет доступа; выдумывать статус недопустимо |
| **Won't Have** | Юридические консультации, разбор личных ситуаций, LLM-ответы по нормативке | цена ошибки — правовой статус человека; отвечаем только из справочника |
| **Won't Have** | Хранение медицинских данных и результатов освидетельствования | 152-ФЗ; храним только факт «пройдено / не пройдено» |
| **Won't Have** | Распознавание документов, OCR паспорта | не нужно для результата, повышает риск ПДн |
| **Won't Have** | Всё, что связано с трудовыми мигрантами и патентами | следующий сегмент масштабирования, не MVP |

Блок Won't Have — часть решения: за 14 дней один сценарий, пройденный до конца,
стоит больше набора недоделанных функций.

## Данные

| Данные | Реальные / тестовые / MOCKED | Источник, дата, территория | Что нужно для реальной интеграции |
|---|---|---|---|
| Нормативные сроки процедур | **Реальные** | ФЗ-115 ст. 5 п. 18–19, ст. 5.1, ред. от 26.06.2026; сверка 16.09.2026, РФ | — уже первоисточник; нужна юридическая вычитка человеком |
| Перечень процедур и документов к ним | **Реальные**, требуют вычитки | нормативка + страницы вузов | — |
| Даты пользователя | **Реальные**, вводит сам | пользователь | — |
| Справочник вузов и регионов | **Тестовый**, в MVP только КФУ и Казань | заполняется вручную | нет открытого API; расширяется данными, не кодом |
| Адреса подразделений МВД и уполномоченных клиник | **[MOCKED]**, помечено в UI и в логе | реестр уполномоченных клиник введён с 01.09.2026, открытость — `TBD` | открытые данные или выгрузка от ведомства |
| Факт «процедура пройдена» | **Реальный**, со слов пользователя | пользователь | сверка с МВД невозможна без доступа |

**Правило для нормативных данных:** ни один срок не берётся из знаний модели. Строка
справочника без ссылки на норму и даты сверки в продукт не попадает — это и есть
защита от того, из-за чего продукт вообще существует. Юридическая вычитка справочника
человеком — отдельная задача в `HANDOFF.md`, она блокирует релиз.

## Ограничения, которые честно называем

- Бот не юрист и не заменяет решение МВД; при расхождении с ведомством прав ведомство.
- Адреса пунктов в MVP — тестовые, помечены в интерфейсе и в логе как `[MOCKED]`.
- Сроки действуют для типового случая «студент, въезд на срок свыше 90 дней»;
  нетиповые статусы бот не разбирает и отправляет к службе миграционного сопровождения
  вуза — это ветка «надёжного ответа нет, вот куда обратиться».
