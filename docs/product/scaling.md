# Масштабирование

Статус: план, перенос кодом ещё не доказан.

## Ядро

Подготовка к одному обращению: вопросы → применимая ветка → чек-лист → следующий
шаг → сохранение → напоминание. Общие: интерфейс, авторизация MAX, модель случая,
контроль переходов, аналитика и работа с источниками.

## Переменная часть

Пути ниже **планируемые, ещё не существуют**. После реализации заменить ссылки на
реальные файлы и приложить diff подключения второго контекста.

| Что адаптируется | Планируемое место | Работа при переносе |
|---|---|---|
| Условия и комплектность | `data/scenarios/<university>/<version>.json` | Проверить применимость и ветки; схема валидируется |
| Адреса и каналы | `data/organizations/<university>.json` | Подтвердить подразделение и контакты |
| Нормативные основания | `data/sources/<source>.json` | Даты действия, источник, ответственный за проверку |
| Производственный календарь | `data/calendars/<year>.json` | Только если используем юридические сроки |
| Тексты и язык | `locales/ru/`, `locales/en/` | Проверка перевода; язык не меняет правило |
| Доступ сотрудников | Таблицы организаций и назначений в PostgreSQL | Назначить ответственного, ограничить область доступа |
| Внешняя ИС | Отдельный адаптер при разрешённом доступе | Новый контракт и проверки; без доступа интеграции нет |

Никакого исполняемого кода в JSON: только ограниченные типизированные условия.
Если для нового контекста нужны новые действия или права, это изменение программы,
а не обещание «любая услуга на конфиге».

## Порядок тиражирования

1. КФУ / выбранная группа: владелец процесса подтвердил инструкцию, пользователи
   прошли подготовку, известны исключения. КФУ — кандидат, не партнёр.
2. КНИТУ-КАИ в Казани: кандидат на проверку переносимости между организациями
   одного города. Сначала исследование его процесса; контакта и набора данных нет.
3. Другой регион, например ТГУ в Томске: кандидат для проверки территориальных
   различий. До выхода необходимы местные источники, ответственный и контрольные случаи.
4. Смежное обращение того же студента — только после подтверждения первой ценности.

Доказательство на защите: загрузить два проверенных набора данных в один релиз,
показать различный результат для вузов и одинаковый интерфейс; приложить перечень
реально изменённых файлов, время адаптации и трудозатраты проверки источников.

## Ресурсы и экономика

На каждый вуз нужны ответственный за актуальность, проверка правил, переводы,
поддержка пользователей и способ привлечения. Узкое место — стоимость сопровождения
данных, даже если разработка не ограничена.

Гипотеза покупателя: международное подразделение вуза; ценность для него — меньше
повторяющихся вопросов и неподготовленных обращений. Для студента доступ бесплатный.
Готовность платить не исследована; B2B-лицензия/сопровождение — вариант после пилота,
не основание прогноза выручки. Считать стоимость на завершённую подготовку и часы
сотрудника на обновление одного сценария.
