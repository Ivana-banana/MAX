# Масштабирование

Сведено 16.09.2026 (`D-010`). Самый тяжёлый продуктовый критерий — 35%.
Статус: план; перенос кодом ещё не доказан. Проверка честности этого файла —
колонка «Где живёт» должна ссылаться на реальный файл. Пока пути помечены как
**план**, и код обязан лечь именно так, иначе масштабирование останется словами.

## Ядро (не меняется при переносе)

- **Проблема:** у обязанности есть срок, он считается от личного события пользователя,
  к ней нужен комплект документов, и человек не знает об этом вовремя. Это не про
  миграцию — это про любой дедлайн-процесс с ценой ошибки.
- **Механика:** вопросы → применимая ветка → расчёт дат → чек-лист и следующий шаг →
  сохранение → напоминание → отметка → следующий срок.
- **Движок сроков:** правило вида «срок = базовое событие + N дней (календарных или
  рабочих), повтор через M». План — `src/core/deadlines.ts`.
- **Модель данных:** пользователь, базовое событие, процедура, срок, комплект, отметка,
  напоминание.
- **Общее:** интерфейс, авторизация MAX, контроль переходов, аналитика, работа с
  источниками.
- **Элементы UI:** список со статусом и «осталось N дней», карточка процедуры с
  чек-листом и основанием, кнопки «Сделано» и «Подробнее».
- **Принцип «каждая дата и каждый пункт — со ссылкой на источник и датой сверки».**

Ядро не содержит ни одного названия страны, региона, вуза или процедуры.

## Переменная часть (адаптируется)

Пути **планируемые, ещё не существуют**. После реализации заменить на реальные файлы и
приложить diff подключения второго контекста.

| Что адаптируется | Планируемое место | Работа при переносе |
|---|---|---|
| Нормативные требования и сроки | `src/data/rules/*.json` — процедура, базовое событие, срок, повтор, основание, ссылка, дата сверки | Добавить файл для новой категории; код не трогается |
| Условия и комплектность | `src/data/scenarios/<вуз>/<версия>.json` | Проверить применимость и ветки; схема валидируется |
| Адреса, каналы, организации | `src/data/orgs/<регион>.json` | Подтвердить подразделение и контакты |
| Нормативные основания как объекты | `src/data/sources/<источник>.json` | Даты действия, источник, ответственный за проверку |
| Производственный календарь | `src/data/calendars/<год>.json` | Только если срок считается в рабочих днях |
| Справочники | `src/data/refs/` — страны, режимы въезда, категории пребывания | Расширение списков |
| Тексты и язык | `src/data/i18n/<язык>.json` | Проверка перевода носителем; язык не меняет правило |
| Роли участников | `src/data/orgs/*.json`, поле «принимающая сторона» | Вуз, работодатель, родственник |
| Доступ сотрудников | Таблицы организаций и назначений в хранилище | Назначить ответственного, ограничить область доступа |
| Внешние ИС | Отдельный адаптер в `src/integrations/` при разрешённом доступе | Новый контракт и проверки; без доступа интеграции нет |

**Никакого исполняемого кода в JSON:** только ограниченные типизированные условия.
Если для нового контекста нужны новые действия или права — это изменение программы, а
не обещание «любая услуга на конфиге». Если при переносе меняется хоть один файл в
`src/core/` или `src/bot/`, переменная часть спроектирована неверно.

## Вопросы

| Вопрос | Ответ |
|---|---|
| Где ещё существует аналогичная проблема? | Вузы Казани (КНИТУ-КАИ), вузы других регионов (ТГУ, Томск); далее — иностранные работники по патенту, оформление РВП, РВПО и ВНЖ; за пределами миграции — любой процесс со сроком от личного события |
| Куда масштабируем в первую очередь и почему? | Вузы Казани: тот же регион, те же подразделения МВД и те же уполномоченные клиники — меняется один файл организаций, нормативка не меняется вообще |
| Что переносится без изменений? | Всё ядро: движок сроков, диалог, чек-листы как механика, напоминания, модель данных, элементы UI |
| Что адаптировать? | Файлы из таблицы выше: для нового региона — организации; для новой категории — нормы; для нового языка — тексты |
| Какие данные, интеграции, ресурсы понадобятся? | Открытые или предоставленные ведомством адреса подразделений и реестр уполномоченных клиник; юрист для вычитки норм при каждой новой категории; переводчик-носитель для каждого языка; ответственный за актуальность на стороне вуза |
| Какие риски? | **(1)** Нормы меняются — ровно это и случилось 01.09.2026; устаревший справочник вреднее отсутствия продукта. **(2)** Без процесса сверки с владельцем продукт протухает. **(3)** Пользователь может принять дату из бота за юридический факт — снимается показом основания и дисклеймером. **(4)** Без вуза-партнёра нет канала привлечения. **(5)** Узкое место — стоимость сопровождения данных, а не разработки |
| Следующий шаг после успешного запуска? | Передать вузу роль владельца справочника организаций, сверку норм замкнуть на службу миграционного сопровождения; после этого регионы добавляют вузы, а не разработчики |

## Порядок тиражирования

| Этап | Что делаем | Условие перехода к следующему |
|---|---|---|
| 1 | КФУ, Казань, русский и английский | Владелец процесса подтвердил инструкцию; студенты проходят подготовку; известны исключения. КФУ — кандидат, не партнёр |
| 2 | КНИТУ-КАИ: переносимость между организациями одного города | Добавление вуза = правка файлов данных без релиза кода |
| 3 | Другой регион, например ТГУ в Томске | Есть местные источники, ответственный и контрольные случаи |
| 4 | Новые языки под топ стран происхождения | Перевод проверен носителем, не машиной |
| 5 | Другие категории иностранцев: патент, РВП, РВПО, ВНЖ | Нормы для категории вычитаны юристом |
| 6 | Другие дедлайн-процессы вне миграции | Движок сроков не потребовал изменений на этапах 1–5 |

Этап 6 — проверка исходного тезиса: если ядро действительно не про миграцию, оно
переживёт смену предметной области. Если на этапах 2–5 пришлось править `src/core/`,
дальше идти не нужно.

## Доказательство на защите

Загрузить два проверенных набора данных в один релиз, показать различный результат
для двух вузов при одинаковом интерфейсе; приложить перечень реально изменённых
файлов, время адаптации и трудозатраты проверки источников. Это единственный способ
отличить настоящую переносимость от обещания.

## Ресурсы и экономика

На каждый вуз нужны ответственный за актуальность, проверка правил, переводы,
поддержка пользователей и способ привлечения. Узкое место — стоимость сопровождения
данных, даже если разработка не ограничена.

Гипотеза покупателя: международное подразделение вуза; ценность для него — меньше
повторяющихся вопросов, неподготовленных обращений и просроченных сроков у студентов.
Для студента доступ бесплатный. Готовность платить не исследована; B2B-лицензия или
сопровождение — вариант после пилота, **не основание прогноза выручки**. Считать
стоимость на завершённую подготовку и часы сотрудника на обновление одного сценария.
