# Масштабирование

Самый тяжёлый продуктовый критерий — 35%. Проверка честности этого файла: колонка
«Где живёт в решении» должна ссылаться на реальный файл или конфиг. Пока код не
написан, пути помечены как **план** — и код обязан лечь именно так, иначе
масштабирование останется словами.

## Ядро (не меняется при переносе)

- **Проблема:** у обязанности есть срок, он считается от личного события пользователя,
  и человек об этом не знает вовремя. Это не про миграцию — это про любой
  дедлайн-процесс с ценой ошибки.
- **Механика:** собрать входные данные → рассчитать даты → показать с основанием →
  напомнить → отметить выполнение → поставить следующий срок.
- **Движок сроков:** правило вида «срок = базовое событие + N дней (календарных или
  рабочих), повтор через M». План — `src/core/deadlines.ts`.
- **Модель данных:** пользователь, базовое событие, процедура, срок, отметка, напоминание.
- **Элементы UI:** список со статусом и «осталось N дней», карточка процедуры с
  основанием, кнопки «Сделано» и «Подробнее».
- **Принцип «каждая дата со ссылкой на норму и датой сверки».**

Ядро не содержит ни одного названия страны, региона, вуза или процедуры.

## Переменная часть (адаптируется)

| Что | Где живёт в решении (план) | Что менять при переносе |
|---|---|---|
| Нормативные требования и сроки | `src/data/rules/*.json` — процедура, базовое событие, срок, повтор, основание, ссылка, дата сверки | Добавить файл для новой категории; код не трогается |
| Перечень услуг и организаций | `src/data/orgs/<регион>.json` — вузы, подразделения МВД, уполномоченные клиники | Новый файл на регион |
| Региональные данные | там же | — |
| Справочники | `src/data/refs/` — страны, типы въезда, категории пребывания | Расширение списков |
| Язык и доступность | `src/data/i18n/<язык>.json` | Новый файл на язык; в MVP ru и en |
| Роли участников | `src/data/orgs/*.json`, поле «принимающая сторона» | Вуз, работодатель, родственник |
| Правила и порядок предоставления | `src/data/rules/*.json`, поле «шаги» | — |
| Внешние ИС и интеграции | адаптеры в `src/integrations/`, интерфейс один | Подключение реестров вместо `[MOCKED]` |

Если при переносе в другой регион меняется хоть один файл в `src/core/` или
`src/bot/` — значит переменная часть спроектирована неверно.

## Вопросы

| Вопрос | Ответ |
|---|---|
| Где ещё существует аналогичная проблема? | Вузы Татарстана (КНИТУ-КАИ, КНИТУ-КХТИ, КГМУ — у медвузов доля иностранных студентов высокая); федеральные и опорные вузы других регионов; далее — иностранные работники по патенту, оформление РВП, РВПО и ВНЖ; за пределами миграции — любой процесс со сроком от личного события |
| Куда масштабируем в первую очередь и почему? | Вузы Казани: тот же регион, те же подразделения МВД и те же уполномоченные клиники — меняется один файл `orgs/kazan.json`, нормативка не меняется вообще |
| Что переносится без изменений? | Всё ядро: движок сроков, диалог, напоминания, модель данных, элементы UI |
| Что адаптировать? | Файлы из таблицы выше. Для нового региона — организации; для новой категории иностранцев — нормы; для нового языка — тексты |
| Какие данные, интеграции, ресурсы понадобятся? | Открытые или предоставленные ведомством адреса подразделений МВД и реестр уполномоченных клиник; юрист для вычитки норм при каждой новой категории; переводчик-носитель для каждого языка |
| Какие риски? | **(1)** Нормы меняются — ровно это и случилось 01.09.2026; устаревший справочник вреднее отсутствия продукта. **(2)** Нужен процесс сверки норм с владельцем, иначе продукт протухает. **(3)** Ответственность: пользователь может принять дату из бота за юридический факт — снимается показом основания и дисклеймером. **(4)** Без вуза-партнёра нет канала привлечения |
| Следующий шаг после успешного запуска? | Передать вузу роль владельца справочника организаций, а сверку норм замкнуть на службу миграционного сопровождения; после этого добавлять регионы силами вузов, а не разработчиков |

## Порядок тиражирования

| Этап | Что делаем | Условие перехода к следующему |
|---|---|---|
| 1 | КФУ, Казань, русский и английский | Основной сценарий пройден в MAX; студенты доходят до плана |
| 2 | Остальные вузы Казани | Добавление вуза = правка одного файла данных без релиза кода |
| 3 | Вузы других регионов | Появился владелец справочника организаций на стороне вуза |
| 4 | Новые языки под топ стран происхождения | Перевод проверен носителем, не машиной |
| 5 | Другие категории иностранцев: патент, РВП, РВПО, ВНЖ | Нормы для категории вычитаны юристом |
| 6 | Другие дедлайн-процессы вне миграции | Движок сроков не потребовал изменений на этапах 1–5 |

Этап 6 — проверка исходного тезиса: если ядро действительно не про миграцию, оно
переживёт смену предметной области. Если на этапах 2–5 пришлось править `src/core/`,
дальше идти не нужно.
