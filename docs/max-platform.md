# Платформа MAX: краткая справка для разработки

Проверено 15 сентября 2026 года. Источники — только актуальная документация MAX, официальные репозитории `max-messenger` и реестры npm/PyPI. Перед сдачей нужно ещё раз проверить [историю изменений API](https://dev.max.ru/docs-api/changelog-api): документация активно меняется.

Критично для хакатона:

- использовать `https://platform-api2.max.ru`, а не старый домен `platform-api.max.ru`;
- мини-приложение существует только при чат-боте и должно иметь публичный HTTPS URL;
- основной сценарий должен работать и в мобильном, и в веб-клиенте MAX; часть MAX Bridge в веб-клиенте недоступна, поэтому нужны fallback-сценарии;
- токен хранить только в переменной окружения/секрете, не в репозитории;
- `GET /chats` уже удалён; `POST /chats/{chatId}/members` ограничен с 9 сентября и будет удалён 30 сентября 2026 года — к сдаче на него рассчитывать нельзя ([changelog](https://dev.max.ru/docs-api/changelog-api)).

## 1. API чат-ботов

### Авторизация

- Базовый адрес: `https://platform-api2.max.ru`.
- Токен выдаётся после создания и модерации бота. Передавать его нужно в заголовке `Authorization: <token>`; query-параметр для токена больше не поддерживается.
- Токен можно перевыпустить. Он даёт полный доступ к боту, поэтому его нельзя помещать в код, образ Docker, логи или репозиторий.

Документация: [обзор API](https://dev.max.ru/docs-api), [управление ботом и токеном](https://dev.max.ru/docs/chatbots/bots-create/manage).

### Получение событий

- **Webhook — production-вариант.** Подписка создаётся через `POST /subscriptions`. Endpoint должен быть публично доступен по HTTPS **на порту 443**, иметь сертификат доверенного УЦ (самоподписанный нельзя), вернуть `200 OK` не позднее 30 секунд. Рекомендуется задать `secret` и проверять `X-Max-Bot-Api-Secret`. После восьми часов без успешной доставки бот автоматически отписывается.
- **Long polling — только разработка и тестирование.** `GET /updates`, `limit` 1–1000 (по умолчанию 100), `timeout` 0–90 с (по умолчанию 30), продолжение через `marker`. Без `marker` возвращается только последнее обновление.
- Webhook и long polling одновременно не работают: при активной webhook-подписке polling отключён.

Документация: [настройка webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions), [long polling](https://dev.max.ru/docs-api/methods/GET/updates), [общие рекомендации](https://dev.max.ru/docs/chatbots/bots-coding/prepare).

### Сообщения, кнопки и вложения

- Отправка: `POST /messages` с `user_id` либо `chat_id`; текст — до 4000 символов, форматирование — `markdown` или `html`, `notify` по умолчанию `true` и включает push-уведомление.
- В документации есть только **inline-клавиатура** во вложении `inline_keyboard`. Типы кнопок: `callback`, `link`, `request_contact`, `request_geo_location`, `open_app`, `message`, `clipboard`. На callback отвечают через `POST /answers` — можно изменить сообщение и/или показать одноразовое уведомление.
- Вложения: `image`, `video`, `audio`, `file`, `sticker`, `contact`, `inline_keyboard`, `share`, `location`. Для медиа сначала получают URL/токен через `POST /uploads`, затем передают токен во вложении сообщения. Обработка крупных файлов асинхронна: при `attachment.not.ready` документация советует повтор с увеличивающимся интервалом.

Документация: [отправка сообщения](https://dev.max.ru/docs-api/methods/POST/messages), [загрузка медиа](https://dev.max.ru/docs-api/methods/POST/uploads), [клавиатуры и форматирование](https://dev.max.ru/docs-api), [ответ на callback](https://dev.max.ru/docs-api/methods/POST/answers), [JS/TS-примеры](https://dev.max.ru/docs/chatbots/bots-coding/js).

### Лимиты

| Что | Ограничение |
|---|---:|
| Все запросы к API | до 30 rps |
| Отправка сообщений | до 2 сообщений/с в один диалог, чат или канал |
| Ответы на callback | до 2 ответов/с в один диалог, чат или канал |
| Текст сообщения | до 4000 символов |
| Inline-клавиатура | до 210 кнопок, 30 рядов, до 7 кнопок в ряду; до 3 для `link`, `open_app`, `request_geo_location`, `request_contact` |
| URL кнопки `link` | до 2048 символов |
| Изображение | до 50 МБ **и** не более 7680×7680 px |
| Видео | до 250 МБ |
| Аудио | до 256 МБ **и** не более 60 минут |
| Файл | до 4 ГБ |
| Медиа в сообщении | до 12 изображений/видео суммарно; файл — только один и только вместе максимум с одной клавиатурой |

Источник лимитов: [обзор API](https://dev.max.ru/docs-api), [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages).

### Имя и настройки бота

- Никнейм генерируется платформой автоматически (`idИНН_bot` для организации/ИП, `se(orgid)_bot` для самозанятого). Выбрать или изменить его нельзя.
- После модерации можно изменить остальные данные бота: название, логотип, описание и настройки; изменение основной информации запускает повторную модерацию. Токен не одноразовый — его можно обновить.
- Название: 1–59 символов, без эмодзи. Логотип: 500×500 px, до 5 МБ, JPG/JPEG/PNG. Описание в карточке: до 200 символов.
- Для профиля организации/ИП доступно до 5 ботов, для самозанятого — до 2. Модерация занимает до 48 часов по рабочим дням.

Документация: [создание и модерация](https://dev.max.ru/docs/chatbots/bots-create/create), [редактирование](https://dev.max.ru/docs/chatbots/bots-create/manage).

## 2. Мини-приложения

- Мини-приложение не бывает отдельным сервисом: оно привязывается к уже созданному боту. В настройках бота указывают URL и вариант кнопки запуска: «Открыть», «Старт», «Играть» или без подписи. После этого кнопка появляется в диалоге с ботом.
- URL: только `https://`, до 1024 символов, валидный домен; пробелы не поддерживаются. Статику можно разместить на любом HTTPS-хостинге.
- Открытие: кнопка в профиле/чате бота, inline-кнопка `open_app` или диплинк `https://max.ru/<botName>?startapp=<payload>`. Payload — до 512 символов, только латиница, цифры, `_` и `-`.
- MAX Bridge различает `ios`, `android`, `desktop`, `web`. Для требований хакатона нужно прогнать один и тот же основной сценарий как минимум в мобильном клиенте и в веб-MAX, не полагаясь в обязательной ветке на mobile-only методы.
- На каждом запуске MAX передаёт стартовые данные. `initDataUnsafe` удобно читать, но нельзя считать доверенным; `initData` нужно валидировать на сервере через описанный HMAC-SHA256 алгоритм. Рекомендованный срок актуальности `auth_date` — 1 час.

Документация: [подключение мини-приложения](https://dev.max.ru/docs/webapps/introduction), [MAX Bridge и платформы](https://dev.max.ru/docs/webapps/bridge), [валидация стартовых данных](https://dev.max.ru/docs/webapps/validation), [FAQ](https://dev.max.ru/help/miniapps).

## 3. MAX Bridge

Подключение — CDN-скрипт `https://st.max.ru/js/max-web-app.js`. После загрузки доступен глобальный объект `window.WebApp`; отдельная инициализация самого `WebApp` не нужна. Полное описание: [MAX Bridge](https://dev.max.ru/docs/webapps/bridge).

Доступные группы методов и свойств:

- **Стартовые данные:** `initData`, `initDataUnsafe`, `platform`, `version`, `deviceName`, `getLaunchContext()`.
- **Экран:** `requestScreenMaxBrightness()`, `restoreScreenBrightness()`, `ScreenCapture.enableScreenCapture()`, `ScreenCapture.disableScreenCapture()`, `getViewportSize()`.
- **Контакт:** `requestContact()` возвращает телефон, `authDate` и `hash`; данные разрешено использовать только в текущем мини-приложении.
- **Жизненный цикл и навигация:** `enableClosingConfirmation()`, `disableClosingConfirmation()`, `openLink()`, `openMaxLink()`, `BackButton.show()/hide()/onClick()/offClick()` и `BackButton.isVisible`.
- **Файлы и обмен:** `downloadFile()`, `shareContent()`, `shareMaxContent()`, `openCodeReader()` для QR через камеру или файл.
- **Хранилища:** `DeviceStorage.setItem()/getItem()/removeItem()/clear()`; аналогичные методы `SecureStorage`, где данные шифруются. Secure Storage ограничен 10 ключами на пользователя и бота.
- **Биометрия:** `BiometricManager.init()`, признаки доступности/прав/сохранённого токена/типа/устройства, `requestAccess()`, `authenticate()`, `updateBiometricToken()`, `openSettings()`.
- **Тактильная связь:** `HapticFeedback.impactOccurred()`, `notificationOccurred()`, `selectionChanged()`.
- **NFC:** `NfcManager.init()`, `isInited`, `openSystemSettings()`, `emulateNfcTag()`.

Ограничения совместимости:

- `DeviceStorage` и `SecureStorage` не поддерживаются веб-клиентом;
- биометрия и haptics не поддерживаются desktop/web;
- NFC поддерживается только Android;
- `shareContent()` не поддерживается web;
- `downloadFile()` работает только внутри MAX и не работает в браузере; нужен HTTPS и непосредственный клик пользователя;
- `getLaunchContext()` имеет минимальные версии Android 26.19.2 и iOS 26.20.0.

Следствие для хакатона: определять платформу, проверять наличие метода и давать веб-fallback (серверное хранение, обычная форма/ссылка, QR текстом и т. п.).

## 4. MAX UI

- Провайдер автоматически определяет iOS/Android и светлую/тёмную тему; параметры можно переопределить.
- Основные компоненты: Avatar, Button, CellAction/Header/Input/List/Simple, Counter, Dot, IconButton, Panel, SearchInput, Spinner, ToolButton; Typography; Container/Flex/Grid; EllipsisText/Ripple; Input/Switch/Textarea; Profile.
- Актуальная версия npm на дату проверки: **0.5.0** (опубликована/обновлена 15.09.2026). Пакет и [официальный репозиторий](https://github.com/max-messenger/max-ui) живые.

Документация и каталог компонентов: [MAX UI](https://dev.max.ru/ui).

## 7. Локальная разработка, тестирование и Docker

### Бот

1. Для локальной разработки проще long polling: входящий HTTPS не нужен. У бота не должно быть активной webhook-подписки.
2. Для проверки production-схемы нужен публичный HTTPS-туннель/прокси до локального обработчика. Снаружи URL обязан быть на 443, с сертификатом доверенного УЦ; порт в webhook URL не указывается. Настроить `secret`, отвечать `200` в пределах 30 секунд, тяжёлую работу выполнять после подтверждения доставки.
3. Использовать выданный организаторами токен. Специального sandbox/test-token режима в документации нет. При самостоятельном создании нужен верифицированный профиль и модерация до 48 часов по рабочим дням.

Документация: [long polling](https://dev.max.ru/docs-api/methods/GET/updates), [webhook и TLS](https://dev.max.ru/docs-api/methods/POST/subscriptions), [создание бота](https://dev.max.ru/docs/chatbots/bots-create/create).

### Мини-приложение

1. Запустить обычный локальный web dev server.
2. Вывести его наружу через HTTPS-туннель либо временный HTTPS-хостинг и указать этот публичный URL в настройках бота. Конкретный туннель MAX не предписывает.
3. Открывать приложение кнопкой бота/диплинком и проверять реальные `initData`, Bridge и viewport внутри MAX. URL можно менять в настройках; при стабильном URL новый deploy доступен пользователям без перепривязки.
4. Отдельно пройти основной сценарий в iOS/Android и в web-MAX. Для недоступных в web Bridge-методов предусмотреть явный fallback.

Документация: [HTTPS и подключение](https://dev.max.ru/docs/webapps/introduction), [обновление URL и ограничения](https://dev.max.ru/help/miniapps), [валидация](https://dev.max.ru/docs/webapps/validation).

### Подводные камни Docker и лимит сборки 5 минут

- Не копировать токен в Dockerfile/слои; передавать его при запуске через env/secrets. В репозитории оставить только `.env.example` без значений.
- Зафиксировать версии (`package-lock.json`, `go.sum`, `requirements.txt`/lock), использовать frozen/reproducible install и кэшировать слой зависимостей до копирования часто меняющегося кода.
- Собирать frontend отдельным build-stage, в runtime переносить только результат и production-зависимости; исключить через `.dockerignore` `.git`, `node_modules`, логи, локальные сборки, тестовые артефакты и секреты.
- Не встраивать HTTPS-туннель в обязательный образ. Описать его как внешний сервис проверки; `compose.yaml` должен поднимать локальные компоненты одной командой, а работающая версия в MAX должна оставаться доступной независимо от локальной сборки.
- Проверить CA bundle в минимальном образе: приложение должно доверять TLS `platform-api2.max.ru`, включая требование MAX добавить сертификат Минцифры ([обзор API](https://dev.max.ru/docs-api)).
- Не скачивать браузеры, модели или большие данные на этапе Docker build, если они не нужны основному сценарию. Предзагрузку тестовых данных делать маленькой и детерминированной.
- Замерить чистую сборку без учёта первоначальной загрузки base images: `docker compose build --no-cache`; целевой запас — заметно меньше 5 минут.

## Неизвестно / не нашёл в документации

- Нативный API платежей, invoice, платёжных событий или возвратов для Bot API/Bridge.
- Встроенный планировщик отложенных сообщений/напоминаний. Подтверждена только обычная отправка сообщения с push; расписание должен реализовать backend.
- Официальный Python SDK и официальные SDK для Java/Kotlin/Swift/PHP/Rust/.NET.
- Отдельные тестовые боты, sandbox API, тестовые токены или среда без модерации. Для хакатона токен обещан организаторами, но это условие хакатона, не публичный механизм MAX.
- Официально рекомендованный инструмент HTTPS-туннеля и локальный эмулятор MAX Bridge.
- Точный срок хранения событий long polling и точные ограничения на инициативное сообщение пользователю до запуска им бота.
- Постоянная reply-клавиатура: документирована только inline-клавиатура в сообщении.
- Полная матрица версий клиентов для каждого метода Bridge; на странице явно указаны лишь отдельные ограничения и минимальные версии.
- Версионированный npm-пакет или фиксированная версия CDN для MAX Bridge.
- Гарантия начисления +0,15 за конкретную функцию: решение принимает жюри по работающему end-to-end сценарию и пользовательской ценности.
