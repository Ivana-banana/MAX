# AGENTS.md — правила для coding agents

Перед любой работой **полностью прочитать `CLAUDE.md`** — это канонический набор
правил проекта. Затем `GIT.md`, свою задачу в GitHub Issues (`bash scripts/issues.sh mine`),
`HANDOFF.md` (токен и деплой) и относящиеся к задаче документы из
`docs/`. Условия хакатона — `Забота о людях.md`; PDF — неизменяемый первоисточник.

Краткий обязательный протокол:

1. Начать с `git fetch --prune && git status -sb`; не трогать чужие незакоммиченные
   изменения. Взять задачу: `bash scripts/issues.sh free`, затем `take <N>`.
   **Файлы менять только в worktree задачи**, не в основной копии на `main`:
   `git worktree add .claude/worktrees/<N>-<тема> -b worktree-<N>-<тема> origin/main`,
   вливать через `git push origin HEAD:main` (подробно — `GIT.md`, «Worktree по умолчанию»).
2. Для нетривиальной задачи записать в issue (`issues.sh note`): что меняем, чем
   проверим, что намеренно не трогаем. Найденную погрешность — новым issue.
3. Проверять реальным запуском; основной сценарий — в настоящем MAX. «Должно
   работать» — не результат.
4. Никаких секретов в репозитории: `.env` + `.env.example` с плейсхолдерами.
5. Моки и тестовые данные вместо реальных интеграций явно помечать
   (`[MOCKED: ...]` в логе, отметка в UI и README).
6. Методы API MAX — только из актуальной документации (`docs/max-platform.md`,
   dev.max.ru/docs), не из памяти.
7. Продуктовое или техническое решение — строка в `docs/decisions.md`.
8. Законченный проверенный шаг — отдельный коммит и push по `GIT.md`, только свои
   файлы (`git add <пути>`).
9. Хуков Claude у тебя нет, поэтому перед правкой запускай
   `bash scripts/issues.sh check .` (задача взята?), а перед каждым коммитом и после долгого шага запускай
   `bash .claude/hooks/check-upstream.sh`: он показывает чужие коммиты в `origin/main`,
   которые трогают твои файлы или общие правила. Противоречат твоей задаче —
   остановиться и сказать человеку.

Если правило здесь и в `CLAUDE.md` трактуется по-разному, действует более строгое.
